# Spring Player Evals × PFF Correlation — Design Spec

**Date:** 2026-06-13
**Project:** `Football/SpringPlayerEvals_SymAnalysis`
**Status:** Approved scope (MVP), pending spec review → implementation plan

---

## 1. Goal

Baylor Football ran Spring 2026 1-on-1 exit meetings: every athlete on the roster (99)
was evaluated by four departments — Position Coach (PC), Nutrition (N), Strength &
Conditioning (STR), Academics (AC). A first-pass **keyword** scoring rubric already
exists in the workbook, but it misses nuance (51% of notes scored 0 despite clear
sentiment).

This project adds two layers on top of the keyword pass:

1. **Semantic analysis** of the evaluation notes (holistic, sentiment-aware scoring).
2. **Cross-reference against on-field reality** — PFF grades and snap volume — to see
   whether internal perception tracks what actually happens on the field.

The unifying question: **Does how a player is viewed internally correspond to how they
grade and how much they play?** Answered three ways (layered):

- **Validate** — correlation between internal view and on-field grade / snap volume.
- **Find mis-valued players** — where internal view and PFF reality diverge
  (undervalued: low internal / high PFF; overvalued: high internal / low PFF).
- **Spot future contributors** — rank players whose eval trajectory is strong but who
  have little on-field sample yet (the projection cohort).

## 2. Data Sources (verified)

### 2.1 Spring evals — `2026 Spring Football 1on1 Exiting Meetings.xlsx`
- **`Wide Format`** sheet — the source: 99 athletes, columns `Athlete ID` (1–99),
  `Last Name`, `First Name`, `Position`, `PC Note`, `N Note`, `STR Note`, `AC Note`.
  All 4 notes filled for all 99 athletes (no missing cells). ~70K chars of note text.
- **`Scoring Engine`** sheet — editable +1/−1 keyword lists (positive / negative).
- **`Player Rankings`** sheet — existing keyword-based development scores per department
  (`PC Score`, `N Score`, `STR Score`, …) and an overall rank.
- Positions present: QB 5, OL 16, WR 13, TE 6, RB 6, LB 9, DE 8, DL 9, S 9, STAR 6,
  CB 8, SPECIALISTS 4.

### 2.2 PFF data — `Football/PFF_Data_Project/data/pff.db` (DuckDB, read-only)
- **`pff_grades`** (175,559 rows) — per-player, per-game, long form:
  `pff_player_id`, `grade_type`, `grade_value`, `snap_count`, `season`, `week`,
  `team_id`, `position`, `unit`. Grade types: `offense`, `defense`, `coverage`,
  `discipline`, `pass`, `pass_block`, `pass_rush`, `receiving`, `run`, `run_block`,
  `run_defense`.
- **`players`** — `pff_player_id`, `name`, `position`, `college`, …
- **`player_seasons`** — `pff_player_id`, `season`, `team_id`, `position`,
  `jersey_number`, `height`, `weight`, `current_eligible_year`.
- Baylor `team_id = '118'`. Seasons available: 2023, 2024, 2025.
  Distinct Baylor players per season: 2023 → 76, 2024 → 88, 2025 → 78.
- Durable join key inside PFF is `pff_player_id`. **No crosswalk** exists from spring
  eval `Athlete ID` to `pff_player_id` (the PFF project explicitly defers that to a
  future AMS layer). We build a project-local crosswalk here; we do **not** modify the
  PFF database (read-only).

## 3. Methodology

### 3.1 Semantic scoring (Claude)
For each of the 99 athletes, read all four department notes holistically and produce:
- **Trajectory score 1–5** (5 = strong upward developmental trajectory).
- **Brief rationale** (1–2 sentences citing the signal).
- **Per-department sentiment** (PC / N / STR / AC: positive / neutral / concerning) to
  support cross-department alignment analysis.
- **Tier**: Strong trajectory · Trending positive · Mixed signals · Needs attention.
- **Red-flag boolean**: concerning signals in ≥2 departments.

Theme extraction (most common positive/negative themes by department) is produced as an
aggregate pass over the 99 sets of notes.

Scores are generated by Claude reading the notes — this is the semantic value-add over
keyword matching and cannot be offloaded to mechanical code.

### 3.2 PFF on-field metrics (recency-weighted blend)
Per matched player, compute a single headline grade and a snap figure:
- **Blended overall grade** = recency-weighted average of season overall grade,
  weights **2025 : 2024 : 2023 = 3 : 2 : 1**. A season's "overall grade" is its
  snap-weighted average of the player's primary unit grade (`offense` for offensive
  positions, `defense` for defensive; specialists handled separately / flagged).
- **Blended snaps** = recency-weighted snap volume on the same 3:2:1 scheme (captures
  "how much do they play," recency-aware).
- **Per-season grade + snaps retained** underneath the blend for transparency and to
  derive a **career trend** flag (improving / flat / declining across available seasons).

### 3.3 The crosswalk (the key risk — first-class artifact)
- Auto-match the 99 spring athletes to PFF Baylor players (`team_id='118'`) by
  normalized name (case/punctuation/suffix-insensitive `First Last`), with position as a
  tiebreaker/sanity check.
- Classify each match: **confident** (unique exact normalized match), **fuzzy** (near
  match / position mismatch / multiple candidates), **unmatched** (no PFF Baylor
  history — expected for true freshmen, transfers, walk-ons).
- Emit the crosswalk as a **reviewable table** (`athlete_id`, eval name, candidate PFF
  name(s), pff_player_id, confidence, reason). **User reviews fuzzy/unmatched before any
  correlation runs.** Unmatched players are retained and routed to the future-contributor
  view as the projection cohort — not dropped.

## 4. Unified master schema (one row per athlete)

| field | source |
|---|---|
| athlete_id, last, first, position | Wide Format |
| keyword_score_* (per dept) + keyword_overall + keyword_rank | Player Rankings |
| semantic_trajectory (1–5), semantic_rationale, tier, red_flag | semantic pass |
| dept_sentiment_pc / _n / _str / _ac | semantic pass |
| pff_player_id, match_confidence | crosswalk |
| pff_grade_blended, pff_snaps_blended | PFF blend |
| pff_grade_2025/2024/2023, pff_snaps_2025/2024/2023, career_trend | PFF per-season |
| flags: undervalued / overvalued / watchlist / projection | derived |

## 5. The three analytical views (derived from the master)

1. **Validation** — correlation of internal view vs on-field reality:
   - keyword_overall vs pff_grade_blended; semantic_trajectory vs pff_grade_blended
   - same two vs pff_snaps_blended
   - Report Spearman + Pearson, overall and within position groups where n allows;
     note where keyword vs semantic diverge in predictive value.
2. **Mis-valued players** — standardized internal score vs standardized PFF grade;
   rank the largest positive (undervalued) and negative (overvalued) gaps. Named lists
   with the eval rationale + PFF numbers side by side. Players with no PFF sample are
   excluded from this view (can't be mis-valued with no on-field data).
3. **Future-contributor watchlist** — players with strong semantic trajectory (and/or
   strong keyword) and low/zero blended snaps; the projection cohort (unmatched / few
   snaps) ranked by eval signal. The "who's rising" list.

Plus the original 5 handoff deliverables fall out of the above: trajectory scores +
rationale, tier list, cross-department alignment flags, theme extraction, red flags.

## 6. Deliverables

**MVP (this cycle):**
- **Master Excel workbook** (saved in project dir) — the unified per-athlete table +
  tabs for the crosswalk, the three views, themes, and red flags. The queryable backbone.
- **Written report (markdown)** — correlation findings, mis-valued lists, watchlist,
  theme extraction, red flags; the "what it means" layer.

**Phase 2 (deferred, after findings are trusted):**
- Interactive HTML dashboard (scatter eval-vs-PFF, sortable/filterable table).
- Coach-facing PDF/deck summarizing risers, mis-valued players, validation headline.

## 7. Build sequence

1. **Semantic scoring** — Claude scores all 99 (trajectory, rationale, tier, dept
   sentiment, red flags) + theme extraction. Persist as structured data.
2. **Crosswalk** — auto-match to PFF; emit reviewable table; **user review gate** on
   fuzzy/unmatched.
3. **PFF blend** — compute blended + per-season grade/snaps + career trend for matched
   players (read-only against `pff.db`).
4. **Master workbook** — join keyword + semantic + PFF + flags into one row per athlete;
   write Excel with view tabs.
5. **Report** — compute correlations + outlier lists + watchlist; write markdown.
6. *(Phase 2: dashboard / coach PDF.)*
7. **Memory update** — at a natural break, update KeystoneOS / global memory to register
   this project and its state.

## 8. Risks & decisions

- **Name-match accuracy** is the dominant risk — mitigated by the reviewable crosswalk +
  user gate before correlation. (Decision: build crosswalk as first-class artifact.)
- **Small per-position n** limits within-position correlation — report those as
  directional, lean on roster-wide correlation for the headline. (Decision: report both,
  caveat the small cells.)
- **Newcomers have no PFF data** — by design they populate the watchlist, not the
  correlation. (Decision: flag as projection cohort, retain, don't drop.)
- **Blend weighting (3:2:1) is a choice** — per-season values are retained so the blend
  can be re-derived if the weighting is revisited. (Decision: 3:2:1, snap-weighted within
  season.)
- **PFF DB is read-only** — all PFF access is `SELECT` only; no writes to `pff.db`.
- **Specialists / two-way / position changes** — specialist grades aren't `offense`/
  `defense`; handle/flag separately so they don't distort the blend.

## 9. Success criteria

- A trustworthy crosswalk: every fuzzy/unmatched case surfaced and resolved by the user.
- Master workbook with all 99 athletes, all four views joined, no silent drops.
- Report states the validation correlation(s) with the right statistical caveats, names
  the mis-valued players with side-by-side evidence, and gives a ranked watchlist.
- Original 5 handoff deliverables all present.
- Everything saved in the project directory; no modification of the PFF database.
