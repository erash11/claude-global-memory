# HTML Dashboard Design

**Date:** 2026-03-21
**Status:** Draft
**Topic:** Replace Streamlit dashboard and PDF report with a single self-contained HTML dashboard

---

## Problem

The existing Streamlit dashboard (`src/report/dashboard.py`) does not resemble the reference designs in `ContextBackgroundInfo/`. It uses default Streamlit styling (light theme, table-based roster, tabbed athlete profiles) rather than the dark card-based sports analytics UI shown in the screenshots. The existing `--report` flag generates a PDF via xhtml2pdf that also does not match the reference design.

## Decision

Replace both the Streamlit dashboard and the PDF report with a **single self-contained HTML file** generated by `run_pipeline.py --report` and `run_pipeline.py --report-only`. The HTML file contains all styles, all athlete data, and a small JS layer for interactivity — no server required, works fully offline.

Streamlit (`src/report/dashboard.py`) and its components are removed. `src/report/pdf_report.py` (PDF generator) is removed. Both are replaced by `src/report/html_dashboard.py`.

---

## Design

### Output

`reports/YYYY-MM-DD_team_dashboard.html` — opened automatically in the default browser after generation via `webbrowser.open()`.

### Two Views (JS-toggled)

**View 1 — Roster** (default on load)

- **Alert strip:** horizontal bar listing all red/orange-flagged athletes. Each entry shows athlete name and the `clinical_notes` field from `classified_athletes` as the flag reason.
- **Filter tabs:** ALL · EXPLOSIVE ECC · BALANCED ATHLETIC · ELITE CONCENTRIC · DEVELOPMENTAL, each showing count in parentheses. Active tab filters the card grid by matching `data-group` attribute on each card. Counts are computed by Jinja2 at render time.
- **Sort control:** dropdown — Name (A→Z) / mRSI (high→low) / Power (high→low) / Readiness (worst first). Cards carry `data-name`, `data-mrsi`, `data-power`, and `data-readiness-rank` (1=red, 2=orange, 3=yellow, 4=green) attributes for JS sort.
- **Player card grid:** 4-column responsive grid (→ 2 → 1 on narrow viewports). Each card contains:
  - Player name
  - `display_group` badge (colored pill — see Classification Tier Labels section)
  - `movement_type` badge (gray pill — see Movement Type section)
  - Three metrics: Rel. Power (W/kg) · Ecc Force (N/kg) · mRSI
  - Readiness dot + label (green / yellow / orange / red)
  - Position + body weight (kg)
  - Left border accent in red/orange for flagged athletes
  - `data-group`, `data-id`, `data-name`, `data-mrsi`, `data-power`, `data-readiness-rank` attributes

**View 2 — Athlete Profile** (shown on card click, hidden by default)

One `<div id="athlete-{athlete_id}">` per athlete, all hidden at load. JS shows the clicked athlete's div and hides the roster.

Sections top to bottom:

1. **Back link** `← Back to roster` — hides profile div, shows roster div
2. **Tier 1 flag banner** (red, `display:none` if no flags) — lists each Tier 1 flag from `clinical_notes` with specific metric value and percentile
3. **Player header** — name, `display_group` badge, `movement_type` badge, body weight (kg), test date
4. **Row: Radar + Key Metrics**
   - Left: Team Percentile Profile — inline SVG radar (see Radar SVG section)
   - Right: Key Metrics grid (2-column, 10 cells) — see Key Metrics section
5. **Row: Phase Profile (Tier 2) + Movement Strategy (Tier 3)**
   - Left: three sub-columns (BRAKING / PROPULSIVE / LANDING) each with colored status badge (Strong / Deficit / Monitor / High Risk) and metric breakdown — see Phase Profile section
   - Right: `movement_type` name, description, eccentric duration / countermovement depth / ECC mean velocity stats, FT:CT percentile
6. **Trend strip (vs prior 60-day)** — 5 cells: Rel. Power · Jump Height · RSI-mod · Rel. Force · FT:CT — see Trend section
7. **Row: Strengths & Weaknesses + Interventions**
   - Left: Strengths (metrics above P75, green text) and Weaknesses (metrics below P25, red text)
   - Right: Primary interventions (checkmarks, green) · Secondary (plus signs, gray) · Avoid (dashes, red) — sourced from `prescription` field in `classified_athletes`
8. **Clinical Notes** — full-width panel, `clinical_notes` field from `classified_athletes`

### Dark Theme

## Movement Type Badge

Derived from raw metric values (not stored in `classified_athletes`):

| Condition | Label | Description |
|-----------|-------|-------------|
| `Eccentric Duration` < 450ms **AND** `Countermovement Depth` > 38cm | Fast-Deep | Quick dive to deep position. Aggressive SSC user. |
| `Eccentric Duration` > 600ms **AND** `Countermovement Depth` < 30cm | Slow-Shallow | Cautious dip. Low energy storage. |
| `Eccentric Duration` > 600ms | Slow-Deep | Extended loading, high force tolerance. |
| default | Balanced | Moderate depth and timing. No extreme strategy signature. |

Both `"Eccentric Duration"` and `"Countermovement Depth"` are in `target_metrics` and fetched from `raw_tests`. If either is `None`, default to Balanced.

## Radar SVG

6 axes, equally spaced (60° apart), radius 90. Axes and threshold sources:

| Axis | `raw_tests.metric_name` | Threshold key in `cfg["positions"][pos]` |
|------|--------------------------|------------------------------------------|
| Pk Power | `"Peak Power / BM"` | `peak_power_bm` |
| Rel. Force | `"Eccentric Peak Force / BM"` | **no threshold in config → fallback to 50th percentile** |
| ECC Power | `"Eccentric Peak Power / BM"` | `ecc_peak_power_bm` |
| Jump Height | `"Jump Height (Imp-Mom)"` | **no threshold in config → fallback to 50th percentile** |
| RSI-mod | `"RSI-modified"` | `mrsi` |
| FT:CT | `"Flight Time:Contraction Time"` | **no threshold in config → fallback to 50th percentile** |

**Fallback rule:** if threshold key is absent from `cfg`, treat the athlete's value as the 50th percentile (renders at 50% radius). Do NOT use `ecc_peak_power_bm` (W/kg) as a proxy for `"Eccentric Peak Force / BM"` (N/kg) — they are different physical quantities with incompatible scales.

`render_radar_svg` converts each metric value to a 0–100 percentile score using linear interpolation between P25 (→25) and P75 (→75), clamped to [5, 95]. Maps score to polygon vertex on the corresponding axis.

## Phase Profile (Tier 2)

Three columns: BRAKING · PROPULSIVE · LANDING. Each column has a status badge and metric breakdown.

**Status logic** (same as existing `phase_profile.py`):
- ≥ P75 → **Strong** (green badge)
- P25–P75 → **Monitor** (yellow badge)
- < P25 → **Deficit** (red badge)
- < P10 (estimated as P25 × 0.75) → **High Risk** (bright red badge)

**Braking column metrics** (from `raw_tests`):
- `"Eccentric Deceleration RFD / BM"` → threshold key `edrfd_bm`
- `"Eccentric Peak Force / BM"` → no threshold → display value only
- `"Force at Zero Velocity"` → no threshold → display value only

**Propulsive column metrics:**
- `"Peak Power / BM"` → threshold key `peak_power_bm`
- `"RSI-modified"` → threshold key `mrsi`
- `"Concentric Impulse"` → no threshold → display value only

**Landing column metrics:**
- `"Peak Landing Force / BM"` → no threshold → display value only
- `"Jump Height (FT) Relative Peak Landing Force"` → no threshold → display value only

Column status badge is determined by the worst-performing metric in that column that has a threshold.

## Trend Strip (60-day)

**5 metrics tracked:** Rel. Power · Jump Height · RSI-mod · Rel. Force · FT:CT

**Query to get prior test:**
```sql
SELECT ca.test_id
FROM classified_athletes ca
WHERE ca.athlete_id = ?
  AND ca.test_date <= (current_date - INTERVAL '55' DAY)
ORDER BY ca.test_date DESC
LIMIT 1
```
(55-day window gives a ±5-day tolerance around "60 days ago". DuckDB requires quoted interval value: `INTERVAL '55' DAY`.)

For each of the 5 metrics, fetch the value from `raw_tests` for both the current `test_id` and the prior `test_id`. Compute `delta_pct = (current - prior) / prior * 100`. Display as `▲ +X.X%` (green) or `▼ -X.X%` (red). If no prior test exists within 90 days, omit the delta and show "No prior data".

**Metric name → raw_tests key mapping for trend:**
| Display | `raw_tests.metric_name` |
|---------|------------------------|
| Rel. Power | `"Peak Power / BM"` |
| Jump Height | `"Jump Height (Imp-Mom)"` |
| RSI-mod | `"RSI-modified"` |
| Rel. Force | `"Eccentric Peak Force / BM"` |
| FT:CT | `"Flight Time:Contraction Time"` |

## Python Architecture

### New: `src/report/html_dashboard.py`

**`render_radar_svg(metrics: dict, position: str, cfg: dict) -> str`**

Pure Python. No external dependencies. Steps:
1. For each of 6 axes, read the metric value from `metrics` dict using exact `raw_tests.metric_name` key
2. Look up P25/P75 from `cfg["positions"][position]` using the threshold key from the Radar SVG table above
3. If threshold missing: use score = 50
4. Interpolate: `score = 25 + (value - p25) / (p75 - p25) * 50`, clamped to [5, 95]
5. Convert score (0–100) to radius: `r = score / 100 * 90`
6. Compute vertex: `x = r * sin(angle)`, `y = -r * cos(angle)` (angle = i * 60°, i=0..5)
7. Build SVG string: axis lines, three grid circles (r=30,60,90), polygon, axis labels
8. Return complete `<svg>...</svg>` string

**`build_athlete_context(row: pd.Series, metrics: dict, history: pd.DataFrame, prior_metrics: dict, cfg: dict) -> dict`**

`prior_metrics` is the `raw_tests` dict for the 60-day-prior test (may be empty `{}`).

Returns a dict with all fields needed by the Jinja2 template:
- `display_group`, `group_css_class` — from `final_group` + `ecc_profile` mapping table
- `movement_type`, `movement_desc` — derived from Eccentric Duration + Countermovement Depth
- `body_weight_kg` — from `metrics.get("Bodyweight in Kilograms")`
- `radar_svg` — from `render_radar_svg()`
- `key_metrics` — list of 10 `{label, value, unit}` dicts
- `phase_braking`, `phase_propulsive`, `phase_landing` — each a `{status, badge_css, metrics}` dict
- `trend` — list of 5 `{label, prior, current, delta_pct, direction}` dicts (direction: `up`/`down`/`none`)
- `strengths`, `weaknesses` — lists of metric label strings
- `prescription` — from `row.prescription`
- `clinical_notes` — from `row.clinical_notes`
- `has_flags` — bool, `row.readiness_flag in ("red", "orange")`
- `readiness_rank` — int for JS sort: `{"red": 1, "orange": 2, "yellow": 3, "green": 4}.get(row.readiness_flag, 4)`
- `rel_power_bm` — float, `metrics.get("Peak Power / BM")` — used in card `data-power` attribute (named field, not index-based)

**`render_dashboard(conn, output_path: Path = None) -> Path`**

Caller is responsible for opening and closing `conn`. Steps:
1. If `output_path` is None, default to `Path("reports") / f"{date.today()}_team_dashboard.html"`
2. Create `reports/` directory if absent
3. Load all latest tests via the same query used in current `dashboard.py`
4. For each athlete: load all metrics from `raw_tests`; query prior test_id; load prior metrics; call `build_athlete_context()`
5. Render `src/report/templates/dashboard.html.j2` via Jinja2 with `FileSystemLoader(Path(__file__).parent / "templates")`
6. Write HTML to `output_path`
7. Call `webbrowser.open(output_path.resolve().as_uri())`
8. Return `output_path`

## JS Layer (~60 lines, embedded in template)

```javascript
function showProfile(id) {
  document.getElementById('roster-view').style.display = 'none';
  document.querySelectorAll('.profile-view').forEach(p => p.style.display = 'none');
  document.getElementById('athlete-' + id).style.display = 'block';
}
function showRoster() {
  document.querySelectorAll('.profile-view').forEach(p => p.style.display = 'none');
  document.getElementById('roster-view').style.display = 'block';
}

// Filter tabs — match data-group attribute
document.querySelectorAll('.tab').forEach(tab => {
  tab.addEventListener('click', () => {
    const group = tab.dataset.group;
    document.querySelectorAll('.card').forEach(card => {
      card.hidden = group !== 'all' && card.dataset.group !== group;
    });
    document.querySelectorAll('.tab').forEach(t => t.classList.remove('active'));
    tab.classList.add('active');
  });
});

// Sort — reads data attributes on cards, re-inserts into grid
document.getElementById('sort-select').addEventListener('change', e => {
  const field = e.target.value; // 'name' | 'mrsi' | 'power' | 'readiness'
  const grid = document.getElementById('card-grid');
  const cards = [...grid.querySelectorAll('.card')];
  cards.sort((a, b) => {
    if (field === 'name') return a.dataset.name.localeCompare(b.dataset.name);
    if (field === 'mrsi') return b.dataset.mrsi - a.dataset.mrsi;
    if (field === 'power') return b.dataset.power - a.dataset.power;
    if (field === 'readiness') return a.dataset.readinessRank - b.dataset.readinessRank;
  });
  cards.forEach(c => grid.appendChild(c));
});
```

## Edge Cases

- **Empty roster:** If no athletes in DB, render a "No data — run `python run_pipeline.py` to pull data" message instead of the card grid.
- **Missing metric:** If a metric value is `None`/absent from `raw_tests`, display `"—"` in the UI. Phase status defaults to Monitor. Radar vertex defaults to 50th percentile.
- **No prior test (trend):** If no test exists within 90 days, render `"No prior data"` in the trend strip cell instead of a delta.
- **No `reports/` directory:** Create it in `render_dashboard()` before writing.
- **Athlete with no clinical notes:** Show empty clinical notes panel rather than hiding it.
